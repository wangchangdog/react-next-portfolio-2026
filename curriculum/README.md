# 教科書本文対応の実装教材

教材版は `textbook-walkthrough-2026-09-06` です。Notionの授業ページを進行表とし、このフォルダはその実装例と検証元を管理します。教科書の画像・本文は格納しません。

## 出発点と完成状態

出発点は静的なポートフォリオ雛形です。ページ、スタイル、サンプル記事・作品、クライアント設定、本文表示の安全対策は講師が準備します。初期状態の `lib/posts.ts` と `lib/works.ts` はサンプルデータを返し、CMS接続の解答を先に有効化しません。

学生はNotionのT05→T06→T08→T09→T10→T11→T12を順に進めます。完成状態はプロフィール、CMSのブログと作品の一覧・詳細、画像、本文、Not Found、公開環境、メタデータが動くポートフォリオです。標準回は開始を制限する日付ではありません。完了した学生は次のタスクへ進みます。

## 第5章の採用範囲

- p.120〜131はサービス・API・登録の操作説明として読みます。実際のスキーマはNotionのblogs/worksの4項目を使います。membersは作りません。
- p.132〜136はAPIプレビューとJSONの確認に使います。キーの値は提出させません。
- p.137〜141はSDK、環境変数、クライアント、async/awaitを読む必須範囲です。メンバーページを作らないことと、この説明を飛ばすことは別です。
- p.142〜146は取得したデータへの置換、画像の許可先、更新確認、取得件数の説明として使います。
- p.147〜151のカテゴリー参照は発展課題です。標準スキーマへcategoryを追加しません。
- p.152〜155の全コンテンツ削除と一括インポートは実行しません。学生自身の記事を保持します。
- p.156〜160は型と一覧取得、表示部品への受け渡しに対応させます。ブログを先に実装し、作品へ同じ考え方を適用します。

## 実装例と作業単位

| タスク | 内容 | 置換対象 |
|---|---|---|
| T09-1〜3 | ブログ一覧を取得・表示する | steps/09-posts.ts.txt → lib/posts.ts |
| T09-4 | 作品一覧へ応用する | steps/09-works.ts.txt → lib/works.ts |
| T10-1〜3 | ブログ詳細を取得・表示する | steps/10-posts.ts.txt → lib/posts.ts |
| T10-4 | 作品詳細へ応用する | steps/10-works.ts.txt → lib/works.ts |

各ファイルは追記断片ではなく、そのタスク完了時の全内容です。学生はNotion内の同じコードを使用できます。`09`段階の詳細関数はまだサンプルを返します。CMSのIDをクリックして詳細が見つからないのはT10未実装の状態であり、一覧の失敗ではありません。

`Post.content`と`Work.content`は、初期の段落配列とCMSのHTML文字列の両方を受け取ります。`RichTextBody`は配列をテキストとして、文字列をsanitize-htmlで処理したHTMLとして表示します。学生が途中で既存データを破壊的に変換する必要はありません。旧教材の`html`プロパティではなく、この版は`content`を渡します。

接続後に環境変数が欠けた場合はエラーにします。サンプルへの自動フォールバックで接続成功を装いません。取得は標準では`cache: "no-store"`とし、CMSの公開変更後にブラウザ全体を再読み込みして確認します。最大100件の一覧を扱い、それ以上はページネーションの発展課題です。no-storeはアクセスごとにAPIを使用するため公開規模が増えたら再検証方式を別タスクとして学びます。

404の詳細取得失敗時だけ、一覧APIへの到達を確認してからundefinedを返します。認証・通信障害やAPI自体の404はエラーのまま残します。

## 検証

`scripts/test-curriculum.mjs`は、教材の全内容ファイルを読み込んで、一覧・詳細・空データ・エラー分類・本文サニタイズを確認します。GitHub Actionsはstarter、blog-list、both-lists、blog-detail、completeの5段階にコードを置換してLint、型検査、本番ビルドを行います。completeではHTTP経由で詳細とNot Foundも確認します。

検証用のCMSレスポンスはモックです。実アカウントの権限、画面操作、Vercelへの公開、CMSの実更新反映、ブラウザによる表示確認は講師の受入確認で別に実施します。CI成功と実サービス成功を混同しません。

`scripts/materialize-lesson.mjs`と`mock-cms.cjs`は検証専用です。学生の作業を自動完成させる目的では使用しません。

## 更新手順

1. stepsの実装例を修正し、テストを実行します。
2. Notionの対応するコードを同じ内容へ更新します。
3. 新しい作業フォルダからNotionだけをたどり、途中の確認画面とエラー時の復帰を確認します。
4. ブランチを作成したらPRを開き、完了した確認と未確認の実サービスを区別して記載します。
