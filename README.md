## GitHubへのログインと作成者情報

共有Macでは毎回の授業開始時にGitHub CLI（`gh`）へログインし、終了時にログアウトします。ブラウザの選択と終了処理は[開発環境と授業ルーティーン](https://app.notion.com/p/3cc24b6a67ce81e5b806ce0d6f69230c)に従います。PATを手動で発行する方式は使いません。雛形に `.github/workflows/` が含まれるため、初回pushにも共通手順の `--scopes workflow` を使います。

ログイン後に `gh auth setup-git --hostname github.com` でGitとの認証連携を設定し、自分のGitHubユーザー名を確認します。Privateの配布元を使う場合は、教員が案内する招待を承認し、対象リポジトリへの閲覧権限も確認します。このREADMEによってリポジトリの公開設定やアクセス権が変更されることはありません。

新しく作成・cloneした `react-next-portfolio` の中で、最初のコミット前に次を実行します。引用符内は自分の氏名とメールアドレスに置き換えます。

````bash
git config --local user.name "自分の氏名"
git config --local user.email "自分のメールアドレス"
git config --local --get user.name
git config --local --get user.email
````

図鑑での `--local` 設定は引き継がれません。作成者情報はリポジトリごとに設定し、共有Macでは `--global` を使いません。GitHub CLIへのログインと、コミットに記録する作成者情報は別です。認証連携後は通常の `git push -u origin main` を使い、以前の `git -c credential.helper= ...` は併用しません。

## 起動と確認

Node.js 24系とnpm、Gitを使用します。自分用のリポジトリを作る手順はNotionのT05に記載しています。

````bash
npm install
npm run dev
````

http://localhost:3000 を開きます。最初は環境変数がなくてもサンプルで動きます。再開時のpullは別のPCで保存した変更を取り込む場合だけ、インストールは初回または依存関係の変更時だけ行います。`package-lock.json` は差分を確認し、`package.json` と一緒にコミットします。

````bash
npm run check
npm run test:curriculum
````

checkはLint、TypeScript型検査、本番ビルドです。通常はcheckを1回実行し、同じ3検査を個別に重ねる必要はありません。test:curriculumは教材用コードの検証です。

## microCMS

blogsとworksはリスト形式です。titleはテキストフィールドで必須、descriptionはテキストエリア、contentはリッチエディタ、thumbnailは画像として用意します。後ろの3項目はスキーマ上は任意ですが、提出用記事2件と作品1件には内容と画像を登録します。

`.env.example`を`.env.local`へコピーし、MICROCMS_SERVICE_DOMAINとMICROCMS_API_KEYを設定します。サービスIDにはURLを入れません。キーはGET専用にし、NEXT_PUBLIC_を付けません。APIキーの値をGitHubや提出物へ含めないでください。

この授業では、練習用の無料サービスで発行したGET専用キーに限り、自分の共有Macの作業フォルダの `.env.local` に保存したままで構いません。毎回の削除・再発行は不要です。インターネットへ公開してよいという意味ではなく、個人情報・実務データを扱うサービスや書き込み権限のあるキーは使いません。共有Macを離れる際は、管理画面からログアウトします。

````bash
node --env-file=.env.local scripts/check-cms.mjs
````

T09以降、接続設定の不足をサンプルへ切り替えて隠しません。サイトが表示されただけでなく、自分がCMSで作成したタイトルと更新が反映されることを確認します。

## 課題登録と評価対象の期限

第11回を目安にVercelなどへ公開し、自分のリポジトリURLと公開URLを課題登録フォームへ登録します。登録時点で提出扱いとしますが、この時点で完成したという意味ではありません。雛形の名前・文章・画像・デザインのままでは自分の制作物として評価できないため、期限までに自分なりの形へ仕上げてください。未達の事項は評価基準に応じて減点対象となることがあります。

評価対象は、第14回の授業日である2027年1月23日23:59（日本時間）までにコミットしたコードとREADMEです。授業終了時が期限ではありません。保存した変更をGitHubへプッシュして公開サイトへ反映し、登録したURLから確認できる状態にします。登録済みでURLに変更がなければ、再送信や別の最終提出は不要です。

microCMSの記事・作品・画像も期限までに仕上げます。これらはGitへ自動保存されないため、期限後に修正する場合は変更前後が分かる記録を残します。

期限後も講評会へ向けたバグ修正は行えます。期限までの履歴を書き換えず、別のコミットとして修正を残し、2027年1月30日の第15回開始までに公開してください。期限後の修正によって評価対象の期限が延びるわけではありません。

第15回は全時間を講評会に充て、全員の作品を全員で見ながら、教員が別途用意するGoogleフォームで相互フィードバックを行います。当日に制作・バグ修正や別の振り返り課題を行う時間はありません。
