# React Next Portfolio 2026

2026年度Web基礎後期の学生用雛形です。教材版は `COURSE_VERSION` の `2026-v2` です。

授業の入口は[Notionポータル](https://app.notion.com/p/kyototech/Web-2026-3cc24b6a67ce80a980c7fdcfed1e842a)です。教科書やREADMEを最初から順番に転記せず、Notionのタスク番号、読むページ、変更対象、確認結果を一つずつ追ってください。

## 何を作るか

TOP、プロフィール、作品一覧・詳細、ブログ一覧・詳細を持つポートフォリオを作ります。最初はサンプルが表示されます。Notionの手順でmicroCMSのデータへ接続し、Vercelで公開します。デザインは単一カラムと文字・余白・境界線を基本とした中立的な初期状態です。配色、文字組み、配置は各自で発展させます。

## 個別の進度で進める

各授業日は標準の到達目安です。前提タスクと確認が終われば、日付を待たず次へ進めます。教員は現在のタスクとエラーに応じて支援します。詰まった場合は「タスク番号・変更ファイル・期待する表示・実際の結果」を伝えてください。

## 環境と起動

Node.js 24系を使用します。Next.js、React、TypeScript等の版は `package.json` を基準とし、教科書記載の旧版へ入れ直しません。

````bash
npm install
npm run dev
````

ブラウザで `http://localhost:3000` を開きます。確認は `npm run check`、教材のデータ取得テストは `npm run test:course` です。

## 本文と安全用の部品

`Post.content` と `Work.content` は、初期サンプルからmicroCMS接続後までHTML文字列です。`RichTextBody` は講師提供のサニタイズ用部品です。これにより、途中で本文の配列を文字列へ変える隠れた作業をなくしています。学生は取得・受け渡し・表示結果を学びます。サニタイズの設定を削除しないでください。

## 環境変数

`.env.example` を `.env.local` へコピーします。準備段階では `CONTENT_SOURCE=sample` のまま、microCMSの値を記入します。第9回相当の接続タスクで `CONTENT_SOURCE=microcms` へ変更します。

- `MICROCMS_SERVICE_DOMAIN` はサービスIDだけです。
- `MICROCMS_API_KEY` はGET権限のみのキーです。GitHubやスクリーンショットへ出しません。
- `NEXT_PUBLIC_SITE_URL` は自分の公開URLです。

CMSモードで設定が不足していればエラーとします。接続失敗をサンプル表示で隠しません。接続成功は、自分でCMSに登録したタイトルと、その更新が表示されることで確認します。

## 基本スキーマ

`blogs` と `works` はどちらもリスト形式です。まずブログで学び、作品へ同じ仕組みを適用します。

| フィールドID | 種類 | API上の必須設定 |
|---|---|---|
| title | テキストフィールド | 必須 |
| description | テキストエリア | 任意 |
| content | リッチエディタ | 任意 |
| thumbnail | 画像 | 任意 |

課題としては記事2件、作品1件へ概要・本文・使用できる画像を入れます。API上の任意設定は、未入力でも処理が壊れないことを確かめるためです。コンテンツIDをURLのslugに使い、独自のslugフィールドは作りません。

## 学習経路

| タスク群 | 標準回 | 到達状態 |
|---|---|---|
| 05 | 第5回 | 起動、情報編集、ページ遷移 |
| 06 | 第6回 | CSS、画像、配列・map・props、共通部品 |
| 07 | 第7回 | 既習内容の確認、個別作業、次タスクへの先行 |
| 08 | 第8回 | CMSの登録、公開、APIプレビュー、環境変数 |
| 09 | 第9回 | ブログ一覧を接続し、作品一覧へ応用 |
| 10 | 第10回 | 1件取得、本文、Not Foundと接続エラーの区別 |
| 11 | 第11回 | 公開とCMS更新の反映確認 |
| 12 | 第12回 | メタデータ、画像、アクセシビリティ、計測 |
| 13〜15 | 第13〜15回 | 仕上げ、発展、提出、講評 |

標準経路は `cache: "no-store"` でデータを取得します。更新確認は再読み込みで行います。先読み済み画面の状態とサーバーのデータ取得を混同しません。時間ベースの再検証、検索、カテゴリー、プレビューは発展です。

## 教材の検証用ファイル

`course/steps` はNotionへ掲載したコードを照合・検証するためのスナップショットです。通常の学習ではブランチ変更や自動適用をせず、Notionの操作でファイルを編集します。`course/apply-stage.mjs` は使い捨てCI専用であり、学生の作業場所では実行しません。

旧 `checkpoint/week-*` ブランチは2026-v1の資料です。v2の通常経路では混在させません。復帰は保存済みコミットから行い、変更済みの自分の文章やデザインを全ファイル上書きで失わないようにします。詳しくは `CHECKPOINTS.md` を参照してください。
